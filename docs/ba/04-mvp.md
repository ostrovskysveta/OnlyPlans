# MVP-анализ юзерстори OnlyPlans (объединение)

> Рамка: промт «объединение юзерстори и выбор MVP». Источник: `02-user-stories.md` (US-1…23).
> Скоуп: прототип ключевых сценариев к **8 дек 2026**, команда 4 чел., недельные спринты.
> Версия 0.3 — роли приведены к новой модели (Редактор плана / Сотрудник / Руководитель-Стейкхолдер),
> US-22 (поиск/фильтры) и US-23 (ссылка на Jira) включены в таблицу.

## 1. Обязательные пользовательские сценарии

1. Создать инициативу/задачу, задать этапы, роли/команду и назначить ответственного.
2. Настроить этапы и роли: **Редактор плана** (Продакт/Тимлид/БА) — полный CRUD; **Сотрудник** —
   свои работы и статус своих задач; **Руководитель/Стейкхолдер** — view-only (сроки, владельцы,
   приоритеты). Отображение команд настраивается/скрывается.
3. Спланировать работу во времени (даты/диапазоны, пресеты длительностей), в т.ч. на неделю.
4. Двигать задачу по этапам, видеть статус и прогресс.
5. Видеть всё в списке и в календаре (день/неделя/месяц с масштабированием).
6. Оставлять комментарии (заметки/промежуточные решения) и видеть историю изменений.
7. Сотрудник видит свои работы; руководство — view-only.
8. Данные сохраняются и повторно открываются.

## 4. Минимальный состав прототипа (до 8 дек) и ограничения

**В прототипе:** создание инициативы/задачи → настраиваемые этапы (discovery/delivery) →
роли (Редактор плана / Сотрудник / Руководитель-Стейкхолдер, отображение команд настраиваемо) →
ответственный → срок (с пресетами длительностей) →
статус (без % готовности) → swimlanes по типам → цвета типов (вручную) → поиск/фильтры →
список + **календарь (день/неделя/месяц с зумом)** → комментарии + история → показ пересечений →
поле «зависит от» → свои работы → view-only руководство → поле-рекомендация OKR + поле-ссылка на
Jira → сохранение/повторное открытие.

**Ограничения (компромиссы):**
- **OKR** — поле-рекомендация с вручную внесёнными OKR; **автопривязка/синхронизация с «Майти» — в роадмап**.
- **Jira** — только поле-ссылка; без синхронизации/импорта.
- **Нагрузка** — показ пересечений, **без авто-перегруза** и расчёта доли занятости.
- **Связи** — поле «зависит от», без графов/блокеров.
- **% готовности** — **не в MVP** (только статус); авто-расчёт готовности — в роадмап.
- **Аутентификация** — лёгкая модель прав: Редактор плана (полный CRUD), Сотрудник (свои работы,
  статус своих задач), Руководитель/Стейкхолдер (view-only); корпоративная SSO — в роадмап.
- **Одновременное редактирование** — ограничено (одно открытие на запись).

## 5. Исключено из MVP → в роадмап, и последствия

| Потребность | Куда | Последствия | Предложение |
|---|---|---|---|
| Таймлайн с вехами (US-20) | Роадмап | вехи видны цветом в календаре/списке | использовать календарь; таймлайн — после |
| Автопривязка/синхронизация OKR с «Майти» (US-21 полн.) | Роадмап | OKR вносятся вручную (поле-рекомендация) | референс/поле; автосвязь на стороне «Майти» — после |
| Сложные перекрёстные мульти-командные представления | Роадмап | модель данных поддерживает команды; сложные виды — нет | модель заложить в MVP, представления — после |
| Авто-расчёт % готовности (US-16 полн.) | Роадмап | в MVP только статус | готовность по этапам — после |
| Корпоративная SSO T-Bank | Роадмап | в MVP лёгкая модель прав (Редактор/Сотрудник/View) | SSO-интеграция — после |
| Полная шкала приоритета + отработанность (US-12 полн.) | Роадмап | в MVP простой приоритет | шкала major/minor/normal + отметка — после |

## 6. Вопросы, меняющие состав MVP (решенные)

**Решено:**
- Jira-синхронизация не нужна (поле-ссылка).
- Календарь с зумом — полностью в MVP.
- Мульти-командность — в модель данных, сложные виды в роадмап.
- Роли: Редактор плана (полный CRUD), Сотрудник (свои работы, статус своих задач),
  Руководитель/Стейкхолдер (view-only); отображение команд настраиваемо/скрываемо.
- Пресеты, комментарии + история, показ пересечений, поле «зависит от» — в MVP.
- OKR — ручное поле-рекомендация (автопривязка/«Майти» — в роадмап).
- **Swimlanes — в MVP.**
- **Цвета типов — в MVP (ручная настройка).**
- **Аутентификация** — Редактор/Сотрудник/View-only; корпоративная SSO — в роадмап.
- **Поиск/фильтры (US-22) — в MVP** (команда, этап, ответственный, swimlane/тип, статус готовности,
  важность, срок/период, текстовый поиск).
- **Ссылка на Jira (US-23) — в MVP** (поле-ссылка, без синхронизации).
- **% готовности — не в MVP** (только статус; авто-расчёт — в роадмап).

**Открытых вопросов по составу MVP нет.** Остаются решения по реализации — см. раздел 7.

## 7. Решения для встречи команды

1. Подтвердить состав MVP (строки «MVP» в таблице) и компромиссы (раздел 4).
2. Подтвердить минимальный состав прототипа до 8 дек.
3. Утвердить модель прав: Редактор плана (полный CRUD), Сотрудник (свои работы, статус своих
   задач), Руководитель/Стейкхолдер (view-only) (SSO — в роадмап).
4. Утвердить набор фильтров для MVP (команда, этап, ответственный, swimlane/тип, статус, важность, срок, текстовый поиск).
5. Зафиксировать формат этапов и ролей по умолчанию (Редактор плана / Сотрудник / Руководитель-Стейкхолдер; команды discovery/delivery).
