# MVP-анализ юзерстори OnlyPlans (объединение)

> Рамка: промт «объединение юзерстори и выбор MVP». Источник: `02-user-stories.md` (US-1…21).
> Скоуп: прототип ключевых сценариев к **8 дек 2026**, команда 4 чел., недельные спринты.
> Версия 0.2 — решения пользователя учтены.

## 1. Обязательные пользовательские сценарии

1. Создать инициативу/задачу, задать этапы, роли/команду и назначить ответственного.
2. Настроить этапы и роли (команды discovery/delivery + роли: лид, разработчик, БА и т.д.), отображение команд настраивается/скрывается.
3. Спланировать работу во времени (даты/диапазоны, пресеты длительностей), в т.ч. на неделю.
4. Двигать задачу по этапам, видеть статус и прогресс.
5. Видеть всё в списке и в календаре (день/неделя/месяц с масштабированием).
6. Оставлять комментарии (заметки/промежуточные решения) и видеть историю изменений.
7. Сотрудник видит свои работы; руководство — view-only.
8. Данные сохраняются и повторно открываются.

## 4. Минимальный состав прототипа (до 8 дек) и ограничения

**В прототипе:** создание инициативы/задачи → настраиваемые этапы (discovery/delivery) →
роли/команды (настраиваемое отображение) → ответственный → срок (с пресетами длительностей) →
статус (без % готовности) → swimlanes по типам → цвета типов (вручную) → поиск/фильтры →
список + **календарь (день/неделя/месяц с зумом)** → комментарии + история → показ пересечений →
поле «зависит от» → свои работы → view-only руководство → поле-рекомендация OKR + поле-ссылка на
Jira → сохранение/повторное открытие.

**Ограничения (компромиссы):**
- **OKR** — поле-рекомендация с вручную внесёнными OKR; **автопривязка/синхронизация с «Майти» — на развитие**.
- **Jira** — только поле-ссылка; без синхронизации/импорта.
- **Нагрузка** — показ пересечений, **без авто-перегруза** и расчёта доли занятости.
- **Связи** — поле «зависит от», без графов/блокеров.
- **% готовности** — **не в MVP** (только статус); авто-расчёт готовности — на развитие.
- **Аутентификация** — лёгкая модель прав «владелец + участник + view-only»; корпоративная SSO — на развитие.
- **Одновременное редактирование** — ограничено (одно открытие на запись).

## 5. Исключено из MVP → на развитие, и последствия

| Потребность | Куда | Последствия | Предложение |
|---|---|---|---|
| Таймлайн с вехами (US-20) | Развитие | вехи видны цветом в календаре/списке | использовать календарь; таймлайн — после |
| Автопривязка/синхронизация OKR с «Майти» (US-21 полн.) | Развитие | OKR вносятся вручную (поле-рекомендация) | референс/поле; автосвязь на стороне «Майти» — после |
| Сложные перекрёстные мульти-командные представления | Развитие | модель данных поддерживает команды; сложные виды — нет | модель заложить в MVP, представления — после |
| Авто-расчёт % готовности (US-16 полн.) | Развитие | в MVP только статус | готовность по этапам — после |
| Корпоративная SSO T-Bank | Развитие | в MVP лёгкая модель прав (владелец/участник/view) | SSO-интеграция — после |
| Полная шкала приоритета + отработанность (US-12 полн.) | Развитие | в MVP простой приоритет | шкала major/minor/normal + отметка — после |

## 6. Вопросы, меняющие состав MVP (решенные)

**Решено:**
- Jira-синхронизация не нужна (поле-ссылка).
- Календарь с зумом — полностью в MVP.
- Мульти-командность — в модель данных, сложные виды на развитие.
- Роли расширенные (команды discovery/delivery + роли, настраиваемые/скрываемые).
- Пресеты, комментарии + история, показ пересечений, поле «зависит от» — в MVP.
- OKR — ручное поле-рекомендация (автопривязка/«Майти» — на развитие).
- **Swimlanes — в MVP.**
- **Цвета типов — в MVP (ручная настройка).**
- **Аутентификация — «владелец + участник + view-only»; корпоративная SSO — на развитие.**
- **Поиск/фильтры — в MVP** (команда, этап, ответственный, swimlane/тип, статус готовности,
  важность, срок/период, текстовый поиск).
- **% готовности — не в MVP** (только статус; авто-расчёт — на развитие).

**Открытых вопросов по составу MVP нет.** Остаются решения по реализации — см. раздел 7.

## 7. Решения для встречи команды

1. Подтвердить состав MVP (строки «MVP» в таблице) и компромиссы (раздел 4).
2. Подтвердить минимальный состав прототипа до 8 дек.
3. Утвердить модель прав «владелец + участник + view-only» (SSO — на развитие).
4. Утвердить набор фильтров для MVP (команда, этап, ответственный, swimlane/тип, статус, важность, срок, текстовый поиск).
5. Зафиксировать формат этапов и ролей по умолчанию (команды discovery/delivery).
