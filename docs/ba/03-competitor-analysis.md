# OnlyPlans — Анализ конкурентов (кандидаты на базу)

> Сравнение открытых роадмап/планировочных инструментов как кандидатов на основу для OnlyPlans,
> плюс внутренний Q-planner. Для каждого: ссылка на репозиторий, лицензия, запуск, соответствие
> нашим сценариям (S1–S6) и пробелы. Цель — передать команде кандидатов для проверки запуска.

## Наши сценарии (для оценки соответствия)

| # | Сценарий |
|---|---|
| S1 | Гибкие этапы/статусы: настраиваемые названия и количество отдельно для discovery и delivery |
| S2 | Календарный вид как в Apple: периоды день/неделя/месяц, масштабирование при смене периода |
| S3 | Цветовая маркировка типов задач на календаре |
| S4 | Пресеты длительности активностей (дизайн ~2 нед, сис.анализ ~1–1,5 нед) с переопределением |
| S5 | Промпт-скелет роадмапа (вне MVP, но интересно) |
| S6 | Двухуровневое использование: статусы инициатив (discovery) + детальный план недели (delivery) |
| S7 | Свимлайны по типам инициатив (настраиваемые) |
| S8 | Базовые сущности (must-be): цели, этапы, роли, временные рамки, ответственные |

**Главный вывод по рынку:** ни один open-source кандидат **не даёт Apple-подобного календаря
(день/неделя/месяц с масштабированием)** — это уникальный сценарий, который придётся дорабатывать
на любом кандидате. Также нет готового промпт-скелета роадмапа.

## Кандидаты

### 1. Plane
- **Репозиторий:** https://github.com/makeplane/plane
- **Лицензия:** AGPL-3.0
- **Запуск:** Docker/Docker Compose (однострочник), есть hosted-песочница. **Легко проверить запуск.**
- **Соответствие:** S1 ✅ (кастомные воркфлоу/статусы, кастомные поля); S2 ⚠️ (календарь только месяц, без день/неделя/зум); S3 ⚠️ (цветные метки, ограниченно по типам); S4 ❌; S5 ❌; S6 ✅ (проекты под команды).
- **Пробелы:** нет зум-календаря; этапы привязаны к проекту, а не к команде как первоклассная сущность; нет пресетов длительности; молодой проект, API развивается.
- **Активность:** ~62k звёзд, очень активен.

### 2. OpenProject
- **Репозиторий:** https://github.com/opf/openproject
- **Лицензия:** GPL-3.0
- **Запуск:** Docker (`openproject/openproject`), нужен ~4–8 ГБ RAM. Есть demo.
- **Соответствие:** S1 ✅ (полноценный движок воркфлоу по типам работ); S2 ⚠️ (timeline/Gantt с зумом по шкале дат, но не календарь-вёрстка); S3 ⚠️; S4 ✅ (шаблоны проектов, планирование длительности); S5 ❌; S6 ✅.
- **Пробелы:** тяжёлый (Ruby/Rails), Gantt вместо календарного дня; много церемонии для лёгкого роадмапа; нет промпт-скелета.
- **Активность:** ~17k звёзд, активен, enterprise-уровень.

### 3. Focalboard
- **Репозиторий:** https://github.com/mattermost-community/focalboard
- **Лицензия:** MIT
- **Запуск:** Docker `mattermost/focalboard`, тривиально.
- **Соответствие:** S1 ✅ (кастомные свойства/группы); S2 ⚠️ (календарь месяц, без зум); S3 ✅ (цветовые метки); S4 ❌; S5 ❌; S6 ⚠️ (одна доска слабее для мультикоманд).
- **Пробелы:** **репозиторий архивирован, не поддерживается** (влился в Mattermost Boards) — плохая основа для долгоживущего продукта; нет зум-календаря. **Рекомендация: отклонить по поддержке.**

### 4. Taiga
- **Репозиторий:** https://github.com/kaleidos-ventures/taiga
- **Лицензия:** MPL-2.0
- **Запуск:** Docker (`taigaio/taiga-docker`). Есть demo.
- **Соответствие:** S1 ✅ (кастомные статусы Scrum/Kanban по проекту); S2 ❌; S3 ⚠️; S4 ⚠️ (оценки в story points); S5 ❌; S6 ⚠️ (agile-центричен, много церемонии для discovery).
- **Пробелы:** нет календаря; переписывается (churn); ориентирован на scrum/sprint, избыточен для статусов discovery.

### 5. Vikunja
- **Репозиторий:** https://github.com/go-vikunja/vikunja
- **Лицензия:** AGPL-3.0
- **Запуск:** Docker Compose (localhost:3456), просто. Есть hosted.
- **Соответствие:** S1 ✅ (кастомные колонки-бакеты по проекту); S2 ⚠️ (календарь месяц + CalDAV, без зум); S3 ⚠️ (метки); S4 ❌; S5 ❌; S6 ✅ (мультипроект → две модели этапов).
- **Пробелы:** нет зум-календаря; нет пресетов длительности; нет нативного трекинга времени; календарь — список задач, не канвас.
- **Активность:** ~6k звёзд, активно, **чистая лёгкая кодовая база (Go+Vue) — лучший вариант «взять и достроить».**

### 6. Wekan
- **Репозиторий:** https://github.com/wekan/wekan
- **Лицензия:** MIT
- **Запуск:** Docker (`wekan/wekan`), docker-compose. Просто.
- **Соответствие:** S1 ✅ (кастомные списки по доске); S2 ⚠️ (календарь месяц + iCal, без зум); S3 ✅ (цветные метки + цвета досок); S4 ❌; S5 ❌; S6 ⚠️ (канбан-центричен).
- **Пробелы:** календарь без зум; устаревший стек (Meteor); канбан слаб для discovery-статусов.
- **Активность:** ~21k звёзд, активен, но старый стек.

### 7. LibrePlan
- **Репозиторий:** https://github.com/LibrePlan/libreplan
- **Лицензия:** AGPL-3.0
- **Запуск:** docker-compose, но тяжёлое старое Java-приложение, UI устарел.
- **Соответствие:** S1 ⚠️ (структура WBS/Gantt, не гибкие стадии); S2 ⚠️ (Gantt с шкалой день/неделя, не календарь); S3 ⚠️; S4 ✅ (шаблоны проектов, WBS, оценка длительности); S5 ❌; S6 ⚠️.
- **Пробелы:** не статусный планировщик (а resource/WBS); старый UI; слаб для discovery; малая команда.
- **Активность:** ~360 звёзд, риск поддержки.

### 8. Planka
- **Репозиторий:** https://github.com/plankanban/planka
- **Лицензия:** MIT
- **Запуск:** Docker/Docker Compose, один из самых простых self-host. Есть hosted.
- **Соответствие:** S1 ✅ (кастомные списки + шаблоны досок); S2 ⚠️ (есть календарь, но канбан-центричен, без зум); S3 ⚠️; S4 ⚠️ (встроенный трекинг времени); S5 ❌; S6 ⚠️.
- **Пробелы:** нет зум-календаря; нет пресетов длительности; канбан-центричен.
- **Активность:** современный (Node/React/Postgres), лёгкий для форка.

## Коммерческие SaaS-инструменты (для справки и шаблонов)

Помимо open-source, стоит изучить готовые шаблоны и UX у коммерческих российских инструментов.
Не кандидаты на форк (closed-source), но источник идей для наших фич и шаблонов.

### Краткая сравнительная таблица (S1–S8)

| Инструмент | S1 этапы | S2 календарь | S3 цвета | S4 пресеты | S5 промпт | S6 2 уровня | S7 свимлайны | S8 базовые | Модель |
|---|---|---|---|---|---|---|---|---|---|

| **Weeek** (weeek.net) | ⚠️ | ⚠️ | ✅ | ⚠️ | ❌ | ⚠️ | ⚠️ | ✅ | SaaS |
| **Kaiten** (kaiten.ru) | ✅ | ⚠️ | ⚠️ | ⚠️ | ✅ | ✅ | ✅ | ✅ | SaaS + on-prem |
| **ЛидерТаск** (leadertask.ru) | ⚠️ | ✅ | ✅ | ⚠️ | ❌ | ⚠️ | ❌ | ✅ | SaaS + on-prem |

### Детали и что брать

- **board.vk.company (VK Board)** — это **whiteboard** (аналог Miro/FigmaJam), а не планировщик
  роадмапа. Не подходит как планировщик. Брать только как визуальный слой (шаблоны канбан/CJM/Gantt,
  реальное время, голосования) — для презентации, не как движок планирования.
- **Weeek** (weeek.net) — канбан-таск-менеджер с видами Доска/Неделя/Месяц/Gantt, цветные метки,
  шаблон «roadmap» на канбане, синхронизация CalDAV (Google/Yandex/Apple). Пробелы: нет вида «день»,
  нет зум-календаря, нет AI-промпта, одна модель статусов на доску.
- **Kaiten** (kaiten.ru) — **лучший по фичам**: кастомные колонки/под-этапы/WIP, свимлайны (дорожки),
  иерархия задач, **AI-ассистент из текста** (самое близкое к промпт-скелету), шаблоны роадмапа
  в блоге. Пробелы: нет Apple-подобного зум-календаря, цвет маркируется тегами, пресеты длительности
  не первоклассные.
  **Шаблоны Kaiten из блога** (стоит перенять): **Timeline** (квартальные доски + декомпозиция на дочерние
  карточки), **Now-Next-Later** (приоритет по близости, поле «уверенность»), **Goal-Oriented** (колонки целей ×
  свимлайны горизонтов, OKR-стиль), **Value-Based** (ценность × усилия), **Kanban-Roadmap** (WIP-лимиты).
  Это напрямую ложится на нашу двухуровневую модель «инициатива(discovery) + недельный план(delivery)».
- **ЛидерТаск** (leadertask.ru) — таск-менеджер с **мультишкальным календарём** (день, 5 дней, неделя,
  месяц, год, 10 лет) — референс для нашего зум-календаря (S2). Статусы фиксированные (нет двух команд),
  нет свимлайнов, нет пресетов, нет AI-промпта.

> Вывод: **Kaiten** — лучший коммерческий ориентир (S1/S5/S6/S7/S8 закрыты), слабое место — зум-календарь
> и пресеты длительности. **ЛидерТаск** полезен как референс переключения периодов календаря.
> **board.vk.company** и **Weeek** — для шаблонов/UX, не как ядро.
> Уникальная дифференциация (S2 зум-календарь, S3 цвета по типам, S4 пресеты) — пробел у всех конкурентов.

## Рекомендация команде на проверку запуска

1. **Plane** — ближе всего по фичам (календарь, воркфлоу, кастомные поля), легко запустить.
2. **Vikunja** — лёгкий, чистый, лучший кандидат под «взять и достроить» календарь/пресеты.
3. **Planka** — простейший запуск, современный стек (Node), подходит как база.
4. **OpenProject** — если нужны пресеты длительности и планирование из коробки (тяжёлый).
5. **Q-planner** (внутренний) — проверить, есть ли переиспользуемая база.

> Уникальные для нас сценарии — зум-календарь (S2) и промпт-скелет (S5) — на всех кандидатах
> потребуют доработки. Это осознанное решение, зафиксированное в `01-vision-and-scope.md` (раздел 3).
