# OnlyPlans — Глоссарий

| Термин | Определение |
|---|---|
| Инициатива | Бизнес-замысел; не хранится отдельной сущностью. |
| Idea (идея) | Сохраняемый объект Discovery: проблема/гипотеза и решение о продолжении либо отклонении. |
| Discovery | Проработка идей до решения; не обязательный этап эпика. |
| Epic (эпик) | Контейнер работ Delivery, связанный с Idea опционально. Одна Idea может породить несколько Epic. |
| Delivery | Планирование и реализация через эпики, этапы и задачи. |
| Stage (этап) | Настраиваемая часть Epic с собственной длительностью и датами. Может быть пустой. Допустимость пустого этапа формально уточняется. |
| Task (задача) | Конкретная работа, обязательно принадлежит одному этапу. |
| Шаблон этапов | Повторно используемый набор этапов без задач; при применении создаёт независимую копию структуры в Epic. |
| Пресет длительности | Настраиваемое значение типовой длительности этапа в рабочих днях. |
| Рабочий день | Понедельник–пятница; праздники в MVP не учитываются. |
| Магнитное планирование | Всегда активное правило автоматического сдвига следующих этапов/задач при изменении плана, с предпросмотром и подтверждением. |
| FS-зависимость | Finish-to-Start: последующая задача не должна начинаться раньше завершения предшествующей. |
| «Не начинать до» | Мягкое ограничение на дату начала задачи, допускающее несколько дат с комментариями и неблокирующие предупреждения. |
| Фактическое начало | Начало работы первым исполнителем; точное событие фиксации — открытый вопрос. |
| Общий процент задачи | Показатель, автоматически выводимый из статуса задачи; таблица соответствия статусов — открытый вопрос. |
| Исполнитель | Участник, назначенный на задачу; исполнителей может быть несколько. |
| Представление по идеям | Роадмап с группировкой связанных эпиков по Idea; технические эпики отображаются отдельно. |
| Представление по исполнителям | Роадмап с задачами в разрезе назначенных людей. |
| Пересечение | Совпадение запланированных рабочих дней задач одного человека; не является измерением загрузки. |
| История изменений | Записи о том, кто и когда изменил объект/поля. |
| История нарушений | Отдельные события нарушения мягких ограничений; Post-MVP. |
| Администратор / редактор / наблюдатель | Три роли MVP; точные разрешения требуют утверждения. |
| Тип задачи | Классификация работы, отличная от этапа и статуса. |
| Статус задачи | Текущее состояние выполнения, используемое также для расчёта общего процента. |

## Не смешивать
Инициатива ≠ Idea; Idea ≠ Epic; этап ≠ тип задачи ≠ статус; шаблон ≠ экземпляр этапа; история изменения ограничения ≠ история его нарушения; пересечение ≠ перегрузка. Слова «фича» и «инициатива» из прежней модели не использовать как имена сохраняемых сущностей.
