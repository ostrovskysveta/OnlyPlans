# OnlyPlans — Бизнес-правила

## Структура
1. Роадмап содержит инициативы.
2. Инициатива имеет тип «идея» или «исследовательская инициатива».
3. Инициатива может не иметь фичи; фича создаётся внутри инициативы.
4. Этап принадлежит одной фиче; состав и порядок этапов задаёт пользователь.
5. Задача принадлежит одному этапу.
6. В MVP родительская и дочерние задачи находятся в одном этапе.
7. У задачи один тип и один текущий статус из справочников роадмапа.

## Справочники и вехи
8. Типы задач и статусы общие для всех фич одного роадмапа.
9. Владелец и редактор могут создавать, переименовывать, менять порядок/цвет и архивировать типы и статусы.
10. Используемые значения не удаляются физически без переназначения задач.
11. Терминальные статусы являются веховыми статусами: например, «Готово к тестированию» и «Готово к релизу».
12. При переходе задачи в терминальный/веховый статус система фиксирует событие-веху с датой и задачей. Последующее изменение текущего статуса не удаляет событие из истории.

## Представления
13. Представления используют одну запись задачи, не копии.
14. Одна задача может присутствовать в нескольких представлениях.
15. Видимость задаётся для пользователя + представления + задачи.
16. Скрытие не удаляет задачу и не меняет её общие поля, назначение, статус или права доступа.
17. Видимость родителя не наследуется дочерними задачами в MVP.
18. Изменение общих полей отображается во всех представлениях, где задача видима.

## Права
19. Роль назначается отдельно в каждом роадмапе.
20. Владелец управляет роадмапом, участниками и имеет все права редактора.
21. Редактор изменяет общие данные и настройки.
22. Читатель просматривает данные и комментирует, но не меняет общие поля.
23. Назначенный исполнитель-читатель может менять статус только назначенной ему задачи.
24. Исполнитель-читатель не меняет сроки, тип, приоритет, описание, этап и назначения.
25. Все три роли могут комментировать доступные им объекты.
26. Назначение в одном роадмапе не даёт прав в другом.

| Действие | Владелец | Редактор | Читатель | Читатель-исполнитель |
|---|---|---|---|---|
| Просмотр | Да | Да | Да | Да |
| Создание/изменение инициатив, фич, этапов | Да | Да | Нет | Нет |
| Изменение общих полей задачи | Да | Да | Нет | Нет |
| Смена статуса назначенной задачи | Да | Да | Нет | Да |
| Смена статуса чужой задачи | Да | Да | Нет | Нет |
| Настройка типов/статусов | Да | Да | Нет | Нет |
| Управление участниками | Да | Нет | Нет | Нет |
| Комментарии | Да | Да | Да | Да |
| Персональная видимость | Да | Да | Да | Да |

## Исполнители и пересечения
27. У задачи ноль, один или несколько исполнителей; назначаются участники роадмапа.
28. Несколько исполнителей не создают копии задачи; отображение визуально делится на части по людям.
29. Пересечения считаются отдельно по каждому исполнителю.
30. Минимальная единица пересечения — один рабочий день.
31. Суббота и воскресенье не учитываются; MVP считает рабочими понедельник–пятница.
32. Задачи без исполнителя отображаются, но не участвуют в персональных пересечениях.
33. Пересечение — предупреждение, не доказательство перегрузки.

## Зависимости, даты и аудит
34. Зависимость связывает две разные задачи; циклы запрещены.
35. Нарушение порядка дат вызывает предупреждение, автопереноса нет.
36. Сроки родителя и дочерних объектов хранятся отдельно; несоответствие вызывает предупреждение, автоматической правки нет.
37. Дата окончания сама по себе не завершает задачу.
38. Пресет задаёт начальную длительность, которую можно изменить для задачи независимо.
39. Изменение общих полей фиксируется с автором, временем, старым и новым значением.
40. При чтении задача получает версию; при сохранении сервер проверяет её актуальность.
41. При конфликте сохранение отклоняется; молчаливая перезапись запрещена. Автослияние не входит в MVP.
42. Персональная видимость не меняет версию общей задачи.

## Требуют уточнения
Включительность даты окончания, часовой пояс, единица длительности пресета и возможность повторного выхода из терминального статуса — см. OQ.
