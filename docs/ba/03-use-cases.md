# OnlyPlans — Use Cases

> Юзкейсы (основной + альтернативные потоки) со ссылками на user stories (US-x).
> Сводная матрица «роль → юзкейсы» — в конце документа.

## Акторы

- **Редактор плана** (в юзкейсах — DeliveryLead, DiscoveryPM): **Продакт (Product manager),
  Тимлид (IT teamlead), БА (Бизнес-аналитик)** — создают и редактируют план.
- **Сотрудник** (Developer, DiscoveryAnalyst): Android/iOS/Java Developer, Разработчик, QA Инженер,
  Системный аналитик, Продуктовый аналитик — **смотрит свои работы** и обновляет статус своих задач.
- **Руководитель / Стейкхолдер** (Viewer): Product Lead, руководство стримов, другие команды —
  **view-only** (сроки фич, владельцы, приоритеты).

## UC-1 — Создать инициативу
**Акторы:** Редактор плана. **Связь:** US-1, US-2.

**Основной поток:**
1. Актор создаёт новую инициативу.
2. Система предлагает набор этапов (по умолчанию или настроенный для команды).
3. Актор вводит название, владельца, приоритет; при необходимости — цель, временные рамки,
   ответственного, статус/прогресс, зависимости.
4. Система сохраняет инициативу со статусом «первый этап».

**Альтернативные потоки:**
- **2a.** Нет настроенных этапов → актор задаёт этапы вручную (см. UC-2).
- **4a.** Не заполнено обязательное поле (название) → система не сохраняет, подсвечивает ошибку.

**Постусловие:** Инициатива появилась в списке и доступна для отслеживания статуса.

> Must-be сущности (FR-M1…M9): цели, этапы, роли, временные рамки, ответственные, статус/прогресс,
> приоритет, комментарии/история, связи/зависимости — создаются/редактируются в рамках UC-1 (элемент)
> и UC-3 (статус), связь — в UC-1/UC-4.

## UC-2 — Настроить этапы команды
**Акторы:** Редактор плана. **Связь:** US-2, US-5.

**Основной поток:**
1. Актор открывает настройки этапов своей команды.
2. Система показывает текущий список этапов.
3. Актор переименовывает/добавляет/удаляет этапы.
4. Система сохраняет и применяет к объектам команды.

**Альтернативные потоки:**
- **3a.** Удаление этапа, на котором есть объекты → система запрашивает подтверждение и предлагает перенести объекты на другой этап.

**Постусловие:** У команды свой набор этапов (независимый от другой команды).

## UC-3 — Отследить статусы инициатив
**Акторы:** все роли. **Связь:** US-3.

**Основной поток:**
1. Актор открывает список инициатив.
2. Система отображает инициативы со статусом, приоритетом и отметкой отработанности.
3. Актор фильтрует по статусу/приоритету.

**Альтернативные потоки:**
- **2a.** Инициатив нет → система показывает пустое состояние с подсказкой создать инициативу.

**Постусловие:** Актор видит актуальные статусы.

## UC-4 — Спланировать неделю (delivery)
**Акторы:** Редактор плана. **Связь:** US-4, US-10, US-11.

**Основной поток:**
1. Актор открывает недельный план.
2. Актор создаёт задачу, выбирает этап, назначает исполнителя и период.
3. Система подставляет длительность из пресета (если этап соответствует активности).
4. Актор при необходимости переопределяет длительность.
5. Система отображает задачу на календаре/в списке.

**Альтернативные потоки:**
- **3a.** Нет пресета для этапа → длительность задаётся вручную.
- **4a.** Пересечение с другой задачей исполнителя → система предупреждает (корнер-кейс).

**Постусловие:** Недельный план delivery обновлён.

## UC-5 — Передвинуть задачу по этапам
**Акторы:** Редактор плана, Сотрудник (свои). **Связь:** US-7.

**Основной поток:**
1. Актор открывает задачу.
2. Актор перемещает её на следующий/предыдущий этап.
3. Система обновляет статус задачи и синхронизирует вид.

**Альтернативные потоки:**
- **2a.** Перемещение на «в прод» требует подтверждения → система запрашивает подтверждение.

**Постусловие:** Статус задачи обновлён и виден команде.

## UC-6a — Просмотреть календарный вид
**Акторы:** все роли. **Связь:** US-8.

**Основной поток:**
1. Актор открывает календарный вид.
2. Система отображает задачи по датам с цветовой маркировкой типов.
3. Актор переключает период (день/неделя/месяц) → отображение масштабируется.

**Альтернативные потоки:**
- **2a.** Задач на период нет → система показывает пустой календарь.

**Постусловие:** Актор видит план в разрезе календаря.

---

## UC-6b — Настроить календарный вид
**Акторы:** Редактор плана, Сотрудник. **Связь:** US-8, US-9.

**Основной поток:**
1. Актор открывает настройки календарного вида.
2. Актор задаёт цвета типам задач, период по умолчанию и масштаб.
3. Система сохраняет персональные настройки вида.

**Альтернативные потоки:**
- **3a.** Сброс настроек → система восстанавливает стандартный вид.

**Постусловие:** Настройки применены к календарному виду пользователя.

---

## UC-7 — Настроить пресеты длительностей
**Акторы:** Редактор плана. **Связь:** US-10.

**Основной поток:**
1. Актор открывает пресеты.
2. Актор создаёт пресет «активность → длительность» (например, дизайн → 2 нед).
3. Система сохраняет пресет для переиспользования.

**Альтернативные потоки:**
- **2a.** Дублирующее имя пресета → система предупреждает и предлагает изменить.

**Постусловие:** Пресет доступен при создании задач.

## UC-8 — Просмотреть роадмап (view-only, другие команды)
**Акторы:** все (доступ к чужим/другим роадмапам только для чтения). **Связь:** US-13.

**Основной поток:**
1. Актор открывает роадмап команды.
2. Система отображает статусы и план (только чтение).

**Альтернативные потоки:**
- **2a.** Нет доступа к команде → система отказывает в доступе.

**Постусловие:** Актор видит роадмап без возможности редактирования.

## UC-9 — Настроить свимлайны по типам инициатив
**Акторы:** Редактор плана. **Связь:** US-16.

**Основной поток:**
1. Актор открывает настройки свимлайнов.
2. Актор задаёт типы инициатив (по умолчанию или свои).
3. Система группирует инициативы/задачи по свимлайнам на роадмапе.

**Альтернативные потоки:**
- **2a.** Типы не заданы → система использует набор свимлайнов по умолчанию.

**Постусловие:** Роадмап отображает свимлайны по типам инициатив.

## UC-10 — Управлять нагрузкой исполнителя
**Акторы:** Редактор плана, Сотрудник (своя нагрузка). **Связь:** US-19.

**Основной поток:**
1. Актор открывает недельный план/нагрузку.
2. Система показывает загрузку исполнителя (число инициатив/задач) на неделю.
3. Актор включает/исключает акторов из отображения и фильтрует по разработчикам/акторам.
4. При превышении лимита инициатив система подсвечивает перегруз.

**Альтернативные потоки:**
- **2a.** У исполнителя нет задач на неделю → система показывает нулевую нагрузку.
- **3a.** Фильтр скрыл всех акторов → система показывает пустой вид с подсказкой.

**Постусловие:** Нагрузка видна и учитывается при планировании.

---

## UC-11 — Просмотреть таймлайн с вехами
**Акторы:** все роли. **Связь:** US-20.

**Основной поток:**
1. Актор выбирает таймлайн-вид (одна горизонтальная линия времени).
2. Система отображает инициативы/задачи; терминальные статусы — как `milestone (веха)`.
3. Процессные статусы выделяются цветом; актор переключает отображение.

**Альтернативные потоки:**
- **2a.** Инициатив/вех нет на периоде → система показывает пустой таймлайн.

**Постусловие:** Ключевые точки роадмапа видны в виде таймлайна с вехами.

---

## UC-12 — Искать и фильтровать инициативы
**Акторы:** все роли. **Связь:** US-22.

**Основной поток:**
1. Актор открывает список инициатив.
2. Актор задаёт фильтры (команда, этап, ответственный, swimlane/тип, статус готовности, важность, срок) или текстовый поиск.
3. Система отображает отфильтрованный список.

**Альтернативные потоки:**
- **3a.** Нет совпадений → система показывает пустой результат с подсказкой сбросить фильтры.

**Постусловие:** Актор видит релевантные инициативы.

---

## UC-13 — Оставлять комментарии и видеть историю
**Акторы:** Редактор плана, Сотрудник (свои). **Связь:** US-17.

**Основной поток:**
1. Актор открывает инициативу/задачу.
2. Актор добавляет комментарий (заметку/промежуточное решение) или просматривает историю изменений.
3. Система сохраняет комментарий и фиксирует изменение в истории (кто/когда).

**Альтернативные потоки:**
- **2a.** История пуста → система показывает пустое состояние.

**Постусловие:** Комментарий сохранён; история изменений доступна.
