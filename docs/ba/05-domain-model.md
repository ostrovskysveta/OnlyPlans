# OnlyPlans — Доменная модель

## Сущности и ответственность
| Сущность | Ответственность |
|---|---|
| Team | Команда пользователей |
| User | Учётная запись человека |
| TeamMember | Членство пользователя в команде |
| Roadmap | План, команда, конфигурация и граница доступа |
| RoadmapMember | Роль пользователя в конкретном роадмапе |
| Initiative | Идея или исследовательская инициатива |
| Feature | Продуктовая возможность в рамках инициативы |
| Stage | Этап процесса конкретной фичи, с порядком |
| Task | Конкретная работа внутри этапа; поддерживает родителя и дочерние задачи |
| TaskType | Общий справочник типов задач роадмапа |
| TaskStatus | Общий справочник статусов задач роадмапа, порядок, цвет и признак вехи |
| TaskAssignee | Назначение одного пользователя на задачу; связь M:N |
| RoadmapView | Представление плана, использующее общие данные |
| UserViewVisibility | Персональная настройка видимости задачи в представлении |
| TaskDependency | Зависимость между задачами |
| MilestoneEvent | Факт достижения задачей вехового статуса |
| DurationPreset | Шаблон длительности задачи |
| Comment | Комментарий к объекту |
| ChangeLog | Аудит изменения общего поля |

## Иерархия
**Roadmap → Initiative → Feature → Stage → Task.**
Инициатива может не иметь фичи. Связь Initiative 1:N Feature предполагается и вынесена в OQ-01. Этапы индивидуальны для фичи. Задача обязательно принадлежит этапу. В MVP дочерняя задача находится в том же этапе, что и родительская.

## Границы
- Discovery и Delivery — названия представлений или этапов, не системные сущности.
- Пересечение — вычисляемое значение по TaskAssignee и датам.
- Визуальная полоса исполнителя — проекция назначения, не копия Task.
- Видимость не меняет доступ и общие поля.
- Направление/OKR — не MVP, до решения OQ-11.

## Предлагаемые кардинальности
- Team 1:N Roadmap; Team M:N User через TeamMember.
- Roadmap 1:N RoadmapMember; User M:N Roadmap через RoadmapMember.
- Roadmap 1:N Initiative.
- Initiative 1:N Feature (OQ-01).
- Feature 1:N Stage; Stage 1:N Task.
- Task 0..1:N Task (родительская связь).
- Roadmap 1:N TaskType и TaskStatus.
- Task M:N User через TaskAssignee.
- Roadmap 1:N RoadmapView.
- User M:N Task в контексте RoadmapView через UserViewVisibility.
- Task M:N Task через TaskDependency.
- Task 1:N MilestoneEvent.
- Comment и ChangeLog связаны с целевым объектом через тип+ID; физический способ FK определить при проектировании БД.

## Ограничения целостности
Все дочерние объекты принадлежат одному роадмапу по цепочке родителей. Тип/статус задачи и исполнитель должны относиться к тому же роадмапу. Запрещены циклические зависимости и самозависимость. Персональная видимость уникальна для пары пользователь–представление–задача. Версия задачи меняется при обновлении общих полей, но не при изменении персональной видимости.
