# OnlyPlans — User Stories
> Приоритет: MVP, если не указано иное. Термины и правила см. в [глоссарии](04-glossary.md) и [бизнес-правилах](06-business-rules.md).

## Акторы
- **Владелец:** полный контроль над роадмапом и участниками.
- **Редактор:** изменяет общие данные и конфигурацию роадмапа.
- **Читатель:** просмотр и комментарии.
- **Назначенный исполнитель:** читатель, который дополнительно может менять статус назначенной ему задачи.
Роль задаётся отдельно в каждом роадмапе.

## US-01. Создать роадмап
Как владелец, хочу создать роадмап команды, чтобы вести план в одном месте.
- Роадмап имеет название и команду.
- Владелец добавляет участников и назначает роли.
- Пользователь видит только доступные ему роадмапы.

## US-02. Создать инициативу
Как редактор, хочу создать инициативу типа «идея» или «исследовательская инициатива», чтобы зафиксировать продуктовый замысел.
- Название обязательно; описание, приоритет, ответственный и даты задаются при необходимости.
- Инициатива может существовать без фичи.
- Исследовательская инициатива может завершиться без разработки.
- Создание инициативы не создаёт автоматически фичи, этапы или задачи.

## US-03. Создать фичу
Как редактор, хочу создать фичу внутри инициативы, чтобы описать планируемую продуктовую возможность.
- Фича связана с инициативой.
- Название обязательно; описание, приоритет, ответственный и даты опциональны.
- Кардинальность инициативы и фичи — OQ-01.

## US-04. Настроить этапы фичи
Как редактор, хочу самостоятельно задать этапы и порядок для каждой фичи.
- Этап принадлежит одной фиче.
- Этап имеет название и порядок; описание и даты опциональны.
- Разные фичи могут иметь разные этапы и порядок.
- Discovery/Delivery не являются обязательными этапами.

## US-05. Создать задачу
Как редактор, хочу создать задачу внутри этапа.
- Задача обязательно относится к этапу.
- Название обязательно; тип, статус, приоритет, даты и исполнители задаются согласно настройкам.
- Поддерживаются родительская и дочерняя задачи.
- В MVP родитель и дочерние задачи находятся в одном этапе.

## US-06. Настроить типы задач
Как владелец/редактор, хочу управлять справочником типов задач роадмапа.
- Типы общие для фич роадмапа.
- Можно создавать, переименовывать, менять цвет и архивировать тип.
- Используемый тип нельзя удалить без переназначения связанных задач.

## US-07. Настроить статусы задач
Как владелец/редактор, хочу управлять справочником статусов.
- Статусы общие для фич роадмапа.
- Можно создавать, переименовывать, менять цвет, порядок и архивировать статус.
- Статус может иметь признак вехового.
- Изменение статуса фиксируется в истории.

## US-08. Назначить исполнителей
Как редактор, хочу назначить на задачу одного или нескольких исполнителей.
- Допускается ноль, один или несколько исполнителей.
- Исполнитель должен быть участником роадмапа.
- Несколько исполнителей не создают копии задачи.
- В представлении задача визуально разделяется на части по числу исполнителей.
- Задача без исполнителя отображается, но не участвует в персональных пересечениях.

## US-09. Просматривать календарь
Как участник роадмапа, хочу переключать день/неделю/месяц.
- Задачи отображаются по срокам.
- Доступны фильтры по исполнителю, этапу, типу, статусу и приоритету.
- Представления используют общие записи задач.

## US-10. Настроить персональную видимость
Как пользователь, хочу скрыть задачу в конкретном представлении.
- Задача может отображаться в нескольких представлениях.
- Видимость задаётся для пользователя, представления и задачи.
- Скрытие не удаляет объект, не меняет общие поля и не влияет на других пользователей.
- Дочерние задачи не скрываются автоматически при скрытии родителя.
- Восстановление видимости возвращает ту же задачу.

## US-11. Видеть свои задачи
Как сотрудник, хочу видеть назначенные мне задачи, сроки, тип, статус, этап и фичу.
- Показываются задачи, где пользователь назначен исполнителем.
- Персональная видимость не меняет назначение и общие данные.

## US-12. Обновить статус своей задачи
Как назначенный исполнитель с ролью читателя, хочу менять статус назначенной мне задачи.
- Менять статус можно только у задачи, где пользователь назначен.
- Нельзя менять срок, тип, приоритет, описание, этап или исполнителей без роли редактора.
- Изменение фиксируется в истории.

## US-13. Просматривать пересечения
Как тимлид, хочу видеть пересечения по каждому исполнителю.
- Пересечения считаются независимо для каждого назначенного пользователя.
- Для задачи с несколькими исполнителями визуализируются отдельные полосы по каждому.
- Минимальная единица — один рабочий день.
- Суббота и воскресенье не учитываются.
- Без исполнителя задача не участвует в персональных пересечениях.
- Пересечение — предупреждение, а не доказательство перегрузки.
- В MVP рабочие дни — понедельник–пятница.

## US-14. Отмечать веховые статусы
Как редактор, хочу помечать статус как веховый.
- При переходе задачи в такой статус фиксируется событие с датой.
- Событие связано с задачей и достигнутым статусом.
- Последующий переход в другой статус не удаляет историю события.
- Различие вехового и завершающего статуса — OQ-03.

## US-15. Создать зависимости
Как редактор, хочу связать задачи зависимостями.
- Связь задаёт порядок между двумя разными задачами.
- Циклические зависимости запрещены.
- Нарушение дат вызывает предупреждение.
- Автоматического переноса задач нет.

## US-16. Комментировать
Как участник роадмапа, хочу комментировать инициативы, фичи, этапы и задачи.
- Комментировать могут владелец, редактор и читатель.
- Комментарий содержит автора и дату/время.
- Комментировать можно только доступный для просмотра объект.

## US-17. Смотреть историю
Как участник, хочу видеть историю изменений ключевых полей.
- Фиксируются объект, поле, старое/новое значение, автор и время.
- Минимум: даты, статус, тип, приоритет, исполнители, этап.
- Персональная видимость хранится отдельно от общей истории задачи.

## US-18. Защита от параллельной перезаписи
Как пользователь, хочу получать конфликт при сохранении устаревшей версии.
- При чтении клиент получает версию объекта.
- При сохранении версия проверяется сервером.
- При несовпадении запись отклоняется, пользователь получает актуальные данные и сообщение.
- Автоматическое слияние не требуется; молчаливая перезапись запрещена.

## US-19. Поиск и фильтры
Как участник, хочу находить инициативы, фичи и задачи.
- Поиск по названию.
- Фильтры: приоритет, этап, тип, статус, исполнитель, период.
- Фильтры комбинируются и сбрасываются.
- Недоступные пользователю объекты не показываются.

## US-20. Использовать пресеты длительности
Как редактор, хочу применять пресеты для типовых задач.
- Пресет содержит название и длительность.
- При применении длительность рассчитывается от даты начала.
- Задачу можно изменить без изменения пресета.
- Пресет не создаёт этап и не назначает тип/статус автоматически, если это отдельно не настроено.

## US-21. Переключаться между роадмапами
Как пользователь нескольких команд, хочу видеть доступные мне роадмапы.
- Роль проверяется отдельно в каждом роадмапе.
- Справочники и персональные настройки из разных роадмапов не смешиваются.

## US-22. Просмотр стейкхолдером
Как стейкхолдер-читатель, хочу видеть сроки фич, приоритеты и ответственных.
- Читатель не изменяет общие поля.
- Читатель может комментировать доступные объекты.

## US-23. Направления и цели — Later
Как редактор, хочу группировать инициативы по направлению/цели. Сущность не входит в MVP до подтверждения OQ-11.

## US-24. Интеграции — Later
Jira, внешние календари, импорт/экспорт, уведомления и автоматическое перепланирование рассматриваются после MVP.
