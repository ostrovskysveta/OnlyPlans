# OnlyPlans — User Stories

> Формат: «Как [роль], я хочу [действие], чтобы [ценность]». Приоритеты: High (MVP),
> Medium (важно), Low (позже). Связано с `01-vision-and-scope.md` (F1–F7).

## Роли (акторы)

- **Редактор плана** (Product manager, Тимлид / IT teamlead, Бизнес-аналитик): **создают и
  редактируют план** — инициативы, этапы, роли/команды, сроки, ответственные, пресеты, swimlanes,
  связи, OKR, комментарии. Полные права (CRUD).
- **Сотрудник** (Android/iOS/Java Developer, Разработчик, QA Инженер, Системный аналитик,
  Продуктовый аналитик): **смотрит свои работы** — свои задачи/инициативы, их статусы и сроки,
  свою нагрузку; может обновлять статус своих задач.
- **Руководитель / Стейкхолдер** (Product Lead, руководство стримов, другие команды): **view-only**
  — видит сроки фич, владельцев и приоритеты.

---

## US-1 — Создать инициативу/задачу со сроками, ответственными
> **Как** редактор плана, **я хочу** создать инициативу/задачу, установить для нее сроки и ответственных **чтобы**
> связать глобальную стратегию продукта (OKR) с понятным пошаговым планом, отслеживать сроки, статусы.

**AC:**
- Given я создаю инициативу, When ввожу название и выбираю начальный статус, Then она появляется в списке с текущим статусом.
- Инициатива хранит: название, владельца, приоритет, входящие в нее этапы (при наличии), временные рамки, ответственного.
- Ответственный назначается из списка участников.
- Инициатива привязана к OKR (см. US-20).

## US-2 — Гибко настроить структуру инициативы
> **Как** редактор плана, **я хочу** настраивать названия и количество этапов для каждой инициативы, **чтобы**
> они отражали реальный процесс команды.

**AC:**
- Given нет готового набора этапов, When я задаю свой список этапов, Then он применяется к моим инициативам.
- Этапы можно переименовывать, добавлять и удалять.

## US-3 — Отследить статусы инициатив в списке и календаре
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** видеть все инициативы и их статусы в одном списке, **чтобы**
> понимать, что в работе, а что нет.

**AC:**
- Отображается полный список идей с приоритетом и статусом.
- Видно отработанные и неотработанные инициативы.
- Автоматический расчет % готовности - на развитие.

## US-4 — Планировать неделю с этапами
> **Как** редактор плана, **я хочу** планировать неделю с детальными этапами (например, системный анализ,
> разработка, тестирование, прод), **чтобы** организовать работу команды.

**AC:**
- Задача привязывается к этапу и временному диапазону.
- План недели виден в календаре и списке.

## US-5 — Видеть свои задачи
> **Как** сотрудник, **я хочу** видеть свои задачи и их статусы, **чтобы** знать, что делать.

**AC:**
- Мне видны задачи, назначенные на меня, и их этапы.
- Отображается приоритет и срок.

## US-6 — Передвинуть задачу по этапам
> **Как** сотрудник, **я хочу** передвигать задачу по статусам, **чтобы** обновлять иметь актуальный статус задачи.

**AC:**
- Задачу можно переместить в следующий/предыдущий статус.
- Изменение статуса видно команде сразу.

## US-7 — Календарный вид с масштабированием
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** календарный вид с переключением периодов (день/неделя/месяц) и
> масштабированием, **чтобы** планировать в разрезе календаря удобно и наглядно.

**AC:**
- Доступны периоды: день, неделя, месяц.
- При смене/увеличении периода отображение масштабируется для читаемости.
- Задачи отображаются по датам.
- Онлайн-зум - на развитие.

## US-8 — Цветовая маркировка типов задач
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** назначать типам инициатив/этапов/задач разные цвета, **чтобы** быстро различать их
> на календаре.

**AC:**
- Типу инициативы/этапа/задачи можно задать цвет.
- На календаре инициативы/этапы/задачи отображаются своим цветом.

## US-9 — Пресеты длительностей
> **Как** редактор плана, **я хочу** задавать пресеты длительности активностей (например, дизайн ~2 нед, сис.анализ ~1–1,5 нед),
> **чтобы** быстро набрасывать план.

**AC:**
- Можно создать пресет «активность → длительность».
- При создании задачи из пресета длительность в проекте подставляется автоматически.

## US-10 — Переопределить длительность под проект
> **Как** редактор плана, **я хочу** переопределять длительность задачи/этапа для конкретного проекта, **чтобы**
> учитывать особенности проекта.

**AC:**
- Длительность из пресета можно изменить у конкретной задачи/этапа без влияния на пресет.

## US-11 — Приоритет и отработанность
> **Как** редактор плана / сотрудник , **я хочу** отмечать приоритет (major/minor/normal) и отработанность, **чтобы**
> оценивать роадмап в разных разрезах.

**AC:**
- Приоритет выбирается из {major/minor/normal}.
- Есть отметка «отработано/не отработано».

## US-12 — View-only доступ для руководства
> **Как** руководитель / стейкхолдер, **я хочу** просматривать роадмапы команд, **чтобы**
> быть в курсе статусов и планов.

**AC:**
- View-only пользователь видит роадмапы, но не редактирует их.
- Доступ выдаётся по роли/настройке.

## US-13 — Swimlanes (дорожки инициатив) по типам
> **Как** редактор плана, **я хочу** выделять **swimlanes (дорожки инициатив)** по типам/темам
> инициатив, **чтобы** различать направления на роадмапе.

**AC:**
- Swimlane (дорожка) = тип/тема инициативы (настраивается).
- Инициатива **сохраняет свой swimlane на всём жизненном цикле**: discovery → delivery (не
  меняется при переходе этапов/команд).

## US-14 — Комментарии и история изменений
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** оставлять комментарии и видеть историю изменений по инициативе/этапу/задаче, **чтобы**
> вести обсуждение и отслеживать, что менялось.

**AC:**
- Можно добавить комментарий к элементу.
- Видна история изменений (кто и когда менял статус/поля).

## US-15 — Показ пересечений работ с загрузкой на неделю
> **Как** редактор плана, **я хочу** видеть нагрузку исполнителя на неделю (например,
> сколько инициатив у разработчика) и фильтровать по акторам, **чтобы** не перегружать людей
> и понимать, кому что влезет.

**AC:**
- У исполнителя на неделе отображается загрузка (число инициатив/задач).
- Можно включить/исключить актора из отображения и фильтровать по разработчикам/акторам.
- Виден перегруз (превышение лимита инициатив).

## US-16 — Связи/зависимости
> **Как** редактор плана, **я хочу** связывать инициативы/задачи зависимостями (блокер, «зависит от»), **чтобы**
> учитывать порядок и блокировки при планировании.

**AC:**
- Можно указать зависимость «зависит от» и «блокирует».
- Зависимые элементы отображаются на роадмапе.

## US-17 — Рекомендация по привязке к OKR
> **Как** редактор плана, **я хочу** видеть поле-рекомендацию OKR (OKR вносятся вручную), **чтобы**
> привязывать инициативу к цели без дублирования.

**AC:**
- Поле-рекомендация OKR (OKR вводятся вручную, без дублирования целей).
- Привязка к OKR отображается у инициативы.
- Автопривязка/синхронизация с «Майти» — на развитие.

## US-18 — Ссылка на задачу Jira
> **Как** редактор плана / сотрудник, **я хочу** прикреплять к инициативе ссылку на задачу Jira, **чтобы**
> связывать роадмап с таск-трекером (без автоматической синхронизации).

**AC:**
- У инициативы есть поле-ссылка на Jira.
- Автоматическая синхронизация с Jira — на развитие.

## US-19 — Поиск и фильтры
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** искать и фильтровать инициативы, **чтобы** быстро находить
> нужное среди большого списка.

**AC:**
- Фильтры: команда, этап, ответственный, swimlane/тип, статус готовности, важность, срок (период).
- Текстовый поиск по названию.

## US-20 — Таймлайн с вехами
> **Как** редактор плана / сотрудник / руководитель / стейкхолдер, **я хочу** видеть вариант отображения роадмапа в виде одной горизонтальной
> линии с вехами, **чтобы** быстро оценивать ключевые точки (терминальные статусы).

**AC:**
- Доступен таймлайн-вид (линия времени).
- Терминальные статусы показаны как `milestone (веха)`.
- Процессные статусы выделяются цветом.


## Для обсуждения на добавление в roadmap развития:

- **US-R1.** Промпт-скелет роадмапа: по текстовому запросу набрасывается структура роадмапа.
- **US-R2.** Миграция данных из Excel/Miro-роадмапа.
- **US-R3.** Внешняя календарная интеграция (Apple/Google).
- **US-R4.** Интеграции с внутрибанковскими сервисами (Jira, справочники, SSO и т.п.); глубина
  автосинхронизации задач из Jira и автоматизация привязки к OKR — открытый вопрос.
