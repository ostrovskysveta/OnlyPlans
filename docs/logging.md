# Один журнал для всей команды

Откройте [Логи](../logs/README.md), выберите раздел, затем участника:

- **Работа** — задача, время, токены и результат.
- **Решения** — выбор, причина, альтернативы и последствия.
- **Инструменты** — использованные моды, модели, скиллы, плагины, MCP и инструменты.

README показывает записи обычным текстом, JSON хранит данные для анализа. Это представления одних данных, повторно заполнять их не надо.

## Что сказать агенту

В начале: «Прочитай AGENTS.md. Мой GitHub-логин — ____. Начни сессию и веди журнал работы, решений и инструментов. Задача: ____».

В конце или перед перерывом: «Проверь поджурналы, закрой сессию и добавь журналы вместе с изменениями в PR». При возвращении — новая сессия.

## Команды

Node.js 22+, без npm-зависимостей. Запуск из корня репозитория. start печатает ID; замените SESSION этим значением, HANDLE — подтверждённым GitHub-логином.

~~~sh
node scripts/journal.mjs start HANDLE "Задача" "Агент / модель или unknown"
node scripts/journal.mjs use SESSION mode Default "Рабочий режим"
node scripts/journal.mjs use SESSION skill project-journal "Ведение журналов"
node scripts/journal.mjs decision SESSION "Контекст" "Выбор" "Альтернативы" "Почему" "Последствия"
node scripts/journal.mjs use SESSION plugin "Имя" "Для чего"
node scripts/journal.mjs tokens SESSION reported 12345 "Источник usage и охват"
node scripts/journal.mjs close SESSION "Сделано, проверено, осталось"
node scripts/journal.mjs check
node scripts/journal.mjs report
~~~

Если usage недоступен, ничего оценивать не надо: по умолчанию unavailable/null. Только по явному запросу команда tokens принимает estimated с методом и охватом. Оценка видимого текста не равна оплаченным токенам.

Одна сессия принадлежит одному участнику и рабочему отрезку. Совместная работа — отдельная запись каждого. Время включает ожидание; пересекающиеся сессии нельзя считать активными часами человека. При обрыве оставьте сессию open до подтверждения конца, не подставляйте время возвращения. Для известного окончания с проблемой close принимает вторым аргументом interrupted.

## Хранение

~~~text
logs/
  README.md
  work/<login>/<session>.json
  decisions/<login>/<session>.json
  usage/<login>/<session>.json
~~~

Ссылки соединяют три части сессии. Пустые поджурналы тоже сохраняются: отсутствие решений видно явно. Другие участники появятся после первой сессии — фиктивные папки создавать не надо.

JSON — источник новых данных. Страницы обновляются автоматически; для восстановления выполните node scripts/journal.mjs render. Не редактируйте README журналов вручную. При конфликте общих оглавлений сохраните JSON обеих веток и повторите render.

## Старая история

Старые записи logs и analytics перенесены сюда. Явно связанные пары объединены: время по общему интервалу, токены выбраны один раз (точные предпочтительнее). Все решения и инструменты сохранены с source_session_id. Неизвестные поля старых решений отмечены явно.

original_sources в записи работы содержит ПОЛНЫЕ исходные тексты с путями и SHA-256: все поля, точность времени, токены и формулировки сохранены. Реестр — [migration.json](../logs/migration.json). Это снимки переноса, не параллельные журналы и не дополнительные сессии для подсчёта. Перенос повторно не запускайте. scripts/migrate-journals.mjs оставлен для проверки; дополнительные доказанные пары передаются двумя ID. По одной близости времени сессии не объединяются.

## Проверка PR

Analytics проверяет структуру, целостность переноса, наличие закрытой новой рабочей сессии и актуальность читаемых страниц. Ревьюер проверяет содержание и записи всех участников. Обязательность Analytics задаётся в настройках GitHub отдельно; имя проверки сохранено.
